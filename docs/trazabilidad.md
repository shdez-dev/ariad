## Decisiones técnicas que resuelven pendientes

1. La aplicación es un monolito modular de escritorio con Rust estable y Tauri v2.
2. La interfaz se comunica con la capa de aplicación mediante IPC de Tauri. No se publica una API HTTP, no se abre un puerto de backend y no se integra un WMS, ERP o lector físico.
3. SQLite local con SQLx es la persistencia del prototipo. Las migraciones SQL versionan el esquema.
4. El simulador llama los mismos casos de uso de aplicación que usa la interfaz. El contrato del evento es interno y tipado; no requiere HTTP, MQTT ni un servicio externo.
5. Se usan ubicaciones configuradas manualmente y datos sintéticos. No se afirma que el simulador represente lecturas RFID reales.

Estas decisiones concretan ADR-01 a ADR-07 y DEC-04 a DEC-08. Las versiones 0.2 de Visión y alcance y Requisitos y criterios de aceptación, y la versión 0.9 de Arquitectura y decisiones técnicas registran estas elecciones. ARD-10 define el puente IPC interno; ARD-11 usa ese contrato para mostrar jerarquía y ocupación sin incorporar geometría física ni hardware. Documento AETHER vinculado: Matriz de trazabilidad de requisitos, ID 3a65eb00-0457-4e44-be52-80739fcfc560.

## Revisión parcial de interfaz y accesibilidad de ARD-11 a ARD-15

El 11-11-2026 se volvió a compilar y abrir la aplicación Tauri con un perfil de demostración aislado. En la vista de mapa se comprobaron la jerarquía sintética de zona, pasillo, rack y posiciones, la ocupación guardada y la actualización de la vista; la interfaz muestra `Pasillo` mediante el catálogo español de niveles. Con teclado se recorrió la navegación y las posiciones, se seleccionó una posición y se comprobó que el detalle cargara su pallet, producto, cantidad y estado; el mensaje de estado anunció la selección. En búsqueda transversal, el control conserva el nombre accesible `Buscar productos, pallets o ubicaciones` después de introducir texto y devuelve el producto y la unidad sintéticos esperados.

Se corrigieron los nombres accesibles de los cuatro filtros de productos, ubicaciones, unidades y búsqueda; se aumentó el tamaño y contraste de textos pequeños en el mapa, las tablas, controles, estados y pie de página; y el mapa dejó de presentar el tipo `aisle` en inglés. La revisión independiente del cambio no encontró regresiones claras. En esta sesión se inspeccionaron flujos de alta, edición, desactivación lógica, duplicados y estado vacío en los catálogos de productos y ubicaciones. Se verificaron mensajes de error para SKU duplicado y etiqueta repetida, el bloqueo del traslado cuando no existe una posición activa libre, y los escenarios deterministas de duplicado, etiqueta desconocida, ubicación inválida y destino ocupado, además del recorrido normal ya observado. Ambas vistas ahora enfocan Actualizar cuando la recarga termina cargada o fallida, y conservan el foco actual si otra recarga la desplazó.

Verificación local: `npm run test:catalog-views` (34 pruebas), `npm test` (15 suites, 102 pruebas), `npm run build` y `git diff --check` pasan. Las pruebas instrumentan llamadas de foco en un DOM mínimo; ARD-12 permanece abierta hasta la aceptación visual y de teclado/lector de pantalla en Tauri.

## Automatizar aceptación integrada de escritorio, ARD-11 a ARD-15 y ARD-25

Se incorpora `e2e-tests/inventory.e2e.test.js`, ejecutado contra la build de Windows real en GitHub Actions con Selenium y `tauri-driver`. El recorrido activa el Simulador con teclado, ejecuta por IPC una recepción, asignación, traslado y despacho, abre la unidad y comprueba sus cuatro movimientos y el estado final. Después crea una anomalía de etiqueta desconocida, verifica que la bandeja muestre el intento exacto y persiste su revisión. El runner usa un `APPDATA` temporal y solo datos sintéticos; guarda capturas de resultado como artefactos de CI. Esta prueba integrada cubre WebView, aplicación Rust y SQLite sin lanzar Ariadna en el computador de desarrollo.

La guía de [WebDriver de Tauri](https://v2.tauri.app/develop/tests/webdriver/) y su [configuración de CI](https://v2.tauri.app/develop/tests/webdriver/ci/) documentan la ruta para Windows. El primer CI Windows [#43974414434](https://github.com/shdez-dev/ariad/actions/runs/43974414434) compiló y empaquetó la build, pero falló en el paso de aceptación WebDriver. La inspección del flujo identificó que un intento de etiqueta desconocida conservaba su identificador escaneado como si hubiera una unidad persistida; eso desviaba a la vista vacía de Unidades en lugar de mostrar el intento exacto. La respuesta del simulador ahora informa que no existe ficha para abrir, y la bandeja de alertas usa la etiqueta persistida para decidir si navega a historial o muestra el registro del intento. La prueba cubre un identificador no vacío sin ficha.

Verificación local del ajuste: `npm test` (15 suites, 102 pruebas), `npm run build`, `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`, la prueba Rust `simulator_scenarios_use_cases_and_alert_exact_attempt_records`, `node --check e2e-tests/inventory.e2e.test.js` y `git diff --check` pasan. La repetición E2E en CI está pendiente. No se usa esta cobertura automatizada como sustituto de lector de pantalla manual ni se cierra ARD-25 con un recorrido parcial.
