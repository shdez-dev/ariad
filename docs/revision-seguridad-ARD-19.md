# Revisión técnica de seguridad ARD-19

Fecha: 11 de noviembre de 2026
Estado: revisión de código y configuración completada
Alcance: prototipo local de escritorio Ariadna con Tauri v2, Rust y SQLite.

## Resumen

La interfaz y el núcleo Rust se comunican mediante comandos IPC de Tauri. La ventana principal solo recibe permisos para los 22 comandos de inventario que usa la aplicación. No se habilitan permisos generales de filesystem, shell o red ni se registra una API HTTP local. La interfaz se empaqueta como recursos estáticos; SQLite permanece local.

La revisión encontró tres entradas que requerían límites en el backend: la consulta de búsqueda, el lote de una línea de recepción y la cantidad de líneas recibidas. Se añadieron límites y pruebas para estos casos. Las consultas de SQLx existentes usan sentencias estáticas y valores enlazados con `bind`.

## Hallazgos y tratamiento

| Hallazgo | Tratamiento |
| --- | --- |
| La capacidad `core:default` concedía grupos de permisos de Tauri que no usa la interfaz. | Se reemplazó por permisos explícitos para los 22 comandos propios registrados en `src-tauri/src/lib.rs`. `AppManifest` genera permisos `allow-*` y `deny-*` por comando. |
| La búsqueda confiaba en el límite HTML del frontend. | `SearchInventory` valida hasta 120 caracteres Unicode antes de consultar el repositorio. El campo HTML conserva el límite equivalente. |
| La recepción aceptaba listas y códigos de lote sin límite explícito. | El dominio y el caso de uso limitan cada unidad a 100 líneas y cada lote a 120 caracteres. IPC comprueba la cantidad antes de convertir las líneas. El formulario aplica los mismos límites. |
| La directiva CSP no estaba configurada. | Se añadió una CSP que permite recursos locales y el transporte IPC de Tauri, bloquea objetos y restringe formularios y conexiones. |
| Se debía confirmar la ausencia de API, credenciales y permisos de plugins. | La inspección de configuración y dependencias no encontró API HTTP de negocio, credenciales ni plugins de filesystem, shell o red. |

## Capacidades de Tauri

`src-tauri/capabilities/default.json` aplica la capacidad únicamente a la ventana `main`. Contiene permisos para `create_product`, `get_product`, `list_products`, `search_inventory`, `update_product`, `deactivate_product`, `create_location`, `get_location`, `list_locations`, `update_location`, `deactivate_location`, `get_handling_unit`, `list_handling_units`, `receive_unit`, `store_unit`, `move_unit`, `dispatch_unit`, `record_movement_correction`, `get_movement_history`, `list_alerts`, `mark_alert_reviewed` y `run_simulation`.

`src-tauri/build.rs` limita los comandos del manifiesto a esos mismos nombres. No se concede `core:default` ni se incluyen permisos de plugins. Las definiciones generadas bajo `src-tauri/permissions/autogenerated` describen los permisos individuales de los comandos.

La política CSP configurada es:

```text
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src ipc: http://ipc.localhost; object-src 'none'; base-uri 'self'; form-action 'self'
```

Los comandos personalizados no se consideran una frontera de validación: cada caso de uso Rust valida los datos antes de consultar o cambiar el estado. El frontend crea elementos con APIs DOM y asigna texto mediante `textContent`; no se encontraron usos de `innerHTML` o `document.write` para datos del inventario.

## Persistencia y entradas

Las consultas de SQLite se construyen con SQL estático y enlazan valores mediante SQLx. No se interpolan entradas del usuario en el texto de las sentencias.

Los límites revisados para las entradas cubiertas por ARD-19 son:

| Entrada | Límite | Validación |
| --- | --- | --- |
| Búsqueda de inventario | 120 caracteres | Caso de uso Rust antes de listar registros |
| Código de lote | 120 caracteres | Constructor de línea en el dominio |
| Líneas por unidad recibida | 100 | Adaptador IPC, caso de uso y entidad de dominio |

Se mantienen las validaciones previas para SKU, etiquetas, cantidad positiva, identificadores requeridos, motivo de corrección y jerarquía de ubicaciones.

## Resultado de la inspección

1. Las consultas persistentes de SQLite usan parámetros.
2. No hay `devUrl`, servidor web de negocio ni listener TCP de la aplicación.
3. No hay credenciales ni secretos configurados en el código revisado.
4. No se encontraron dependencias directas de servidor HTTP, filesystem de Tauri, shell de Tauri ni clientes HTTP en `src-tauri/Cargo.toml`.
5. Las capacidades Tauri se limitan a una ventana y a los comandos propios enumerados.
6. La CSP no permite conexiones arbitrarias a hosts remotos.

## Verificación

Después de los cambios pasan 71 pruebas Rust, `cargo fmt --check`, Clippy con `-D warnings`, `npm run build`, las 14 pruebas frontend y `npm run tauri -- build --no-bundle`. Una comprobación de consistencia confirma que los 22 comandos registrados aparecen en `build.rs` y en la capacidad, sin permisos sobrantes ni faltantes.

Esta revisión cubre el código y la configuración del prototipo. No equivale a una auditoría externa ni a una evaluación de seguridad para despliegue productivo. La aceptación visual manual de ARD-11 a ARD-15 continúa pendiente.
